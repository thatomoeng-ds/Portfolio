Closing Balance Reconciliation Validator

VBA automation that cross checks a checklist of linked recon workbooks against their reported closing balances

Internal Automation Project

The Closing Balance Reconciliation Validator is a VBA macro that automates a tedious, error prone month end control: confirming that the "Total Balance (Current)" figure a preparer typed into a master Check list actually matches a value that genuinely exists somewhere in their underlying reconciliation workbook. Instead of a reviewer opening every linked file by hand, the macro follows each hyperlink automatically, searches the recon's Summary or Recon tab for a matching figure, and writes back a clear Upload / Do Not Upload decision with the source tab itself colour coded green or red so the result is visible at a glance even without opening the file.

System Architecture

1 · Input
Master "Check list" sheet
One row per reconciliation: a hyperlink/path to the recon file (col G) and its reported Total Balance (col I)
Linked Recon Workbooks
Dozens of separate .xlsx files, each with either a "Summary" or "Recon" tab
2 · VBA Validation Engine
Read Only Batch Opening
Opens each linked workbook in the background (ReadOnly:=True), one at a time
Summary → Recon Fallback
Prefers a "Summary" tab; falls back to "Recon" if Summary doesn't exist
Whole Sheet Value Search
Scans every cell in the source tab's UsedRange for a number within 0.01 of the reported balance
3 · Output
Upload / Do Not Upload
Written to the Decision column (J) on the master Check list, per row
Colour Coded Source Tabs
The recon's own Summary/Recon tab is tinted green (match found) or red (no match), visible on next open
Exception Reasons
"No link", "Cannot open recon", "Summary or Recon sheet not found" every failure mode is labelled, not silently skipped

The Problem

Month end sign off required a reviewer to manually open dozens of individual reconciliation files, hunt through each one for a "Total Balance" figure, and compare it by eye against what the preparer had typed into a shared Check list, a process that was slow, easy to get wrong on a busy close, and gave no visible record of why a reconciliation had or hadn't been approved for upload.

My Approach & Thought Process

  • Anchored the whole process on three columns. Rather than trying to standardise every recon workbook's layout, I kept the Check list itself as the single control point: column G holds the link/path to the recon file, column I holds the reported Total Balance, and column J is where the macro writes its decision, so the process works no matter how the underlying recon files are structured internally.
  • Made file access resilient with defensive error handling. Every Workbooks.Open and sheet lookup is wrapped in On Error Resume Next / On Error GoTo 0 pairs, so a broken hyperlink, a missing file, or a renamed tab doesn't crash the whole batch, it just records a specific reason ("Cannot open recon", "Summary or Recon sheet not found") on that one row and moves on to the next.
  • Built a Summary first, Recon fallback lookup. Different preparers had settled on different tab names for their totals, so the macro tries wbRecon.Sheets("Summary") first and only falls back to wbRecon.Sheets("Recon") if that fails — covering both conventions without needing every workbook to be re-templated first.
  • Searched for the value itself rather than trusting a fixed cell address. Because recon layouts vary from file to file, the macro loops every cell in the source tab's UsedRange and checks each numeric value against the reported total with a small tolerance (Abs(cellValue - totalBalanceValue) <= 0.01), so it finds the figure wherever it happens to sit, rather than assuming it's always in the same row/column.
  • Turned the result into an at a glance visual signal, not just a text label. In addition to writing "Upload" / "Do Not Upload" back to the Check list, the macro also colours the recon's own source tab green or red so the next person to open that individual workbook sees the outcome immediately, without needing to go back to the master checklist at all.
  • Closed every workbook cleanly regardless of outcome. Each opened recon file is explicitly closed with SaveChanges:=False before moving to the next row, and object references are reset in a shared cleanup label (NextRow:) preventing the macro from leaving dozens of read only workbooks open in the background during a large batch run.

Key Features

  • Fully automated, one click validation of every reconciliation on the Check list in a single run
  • Reads reported totals and links straight from the master Check list no retemplating of existing recon files required
  • Summary then Recon tab fallback covers both naming conventions already in use across the team
  • Tolerant numeric matching (±0.01) makes the check robust to minor floating point/rounding differences
  • Distinct, human readable exception messages for every failure mode instead of a single generic error
  • Visual green/red tab colour coding on the source workbook itself, in addition to the Check list decision column
  • Read only, auto closing workbook handling keeps the process safe to rerun at any time

Impact

  • Replaced a fully manual, file by file review with a single click that validates the entire reconciliation batch
  • Removed reviewer guesswork, every row gets an explicit Upload / Do Not Upload decision with a stated reason on failure
  • Reduced the risk of an incorrect balance being uploaded during month end close due to human oversight
  • Gives preparers immediate, visible feedback (tab colour) on their own recon file without waiting on a reviewer
  • Safe to rerun at any point in the close cycle since every source file is opened read only and closed without saving
