Hackaprompt Contribution Margin Automation

VBA automation engine for monthly and per model contribution margin calculation

Hackaprompt Use Case

The Contribution Margin (CM) Automation is a VBA macro I built during a Hackaprompt use case challenge to replace a fully manual month end calculation. With a single click, it scans a large general ledger style export, isolates the specific accounts that make up contribution margin, and produces both a total monthly CM figure and a CM-per unit breakdown by model (TAIS code), feeding directly into the Cost of Retail Dashboard project.

The Problem

Contribution margin is not a single line item in the raw ledger export, it's the sum of roughly two dozen specific account codes scattered across thousands of rows. Every month, someone had to manually filter the export for those exact accounts, sum the values, and then regroup the result by model to understand which products were actually profitable. Doing this by hand was slow, repetitive, and risked human error, a single missed account code or mistyped filter could throw off the entire monthly figure.

My Approach & Thought Process

  • Started by defining "contribution margin" as data, not as a formula. Rather than hardcoding a single Excel SUMIF, I built a Scripting.Dictionary lookup table of every account code that legitimately belongs to the CM calculation. This makes the definition of CM explicit, auditable, and easy to extend if the chart of accounts changes.
  • Designed a two-pass aggregation strategy. The first pass walks the raw ledger once, matching rows against the account dictionary and accumulating both a grand total and a category-level breakdown in a single loop avoiding the performance cost of scanning the sheet multiple times for different groupings.
  • Solved a messy real world data problem: inconsistent model codes. The TAIS (model) reference embedded in the category label wasn't clean it had leading letters, stray spaces, and even non breaking space characters (Chr(160)) mixed in. I wrote explicit cleaning logic to strip those out and reliably extract the last four characters as the true model key, turning "N  0E91" into the correct "0E91".
  • Ran a second aggregation pass keyed on the cleaned model code, summing the category level results into a final per- TAIS contribution margin giving the business a model by model profitability view derived directly from the same ledger data, with zero manual regrouping.
  • Protected the output from a classic spreadsheet bug. Model codes can look numeric (e.g. "0E91"), which Excel will silently reformat or truncate leading zeros from if left as General format. I explicitly forced the output column to Text format and prefixed values with an apostrophe, guaranteeing every model code displays and stores exactly as intended.
  • Made the output ready for direct reuse. The grand total lands in a single fixed cell, the category breakdown writes to one output range, and the TAIS-level breakdown writes to another all in well-known, stable locations. This predictability is exactly why this macro's grand total cell later became a direct data source read straight into the Cost of Retail Dashboard's Python build pipeline, closing the loop between a manual finance process and a fully automated reporting system.

Key Features

  • One click SumAccountValues macro replaces a multi step manual filter and sum process.
  • Explicit, editable account code dictionary, the definition of "contribution margin" lives in one place.
  • Automatic grand total calculation with proper numeric formatting.
  • Category level CM breakdown as an intermediate, auditable output.
  • Robust TAIS key cleaning that handles inconsistent spacing and hidden characters.
  • Per model CM/unit table with forced text formatting to protect model codes.
  • Designed to be rerun monthly across multiple reporting workbooks with identical logic.

Impact

  • Replaced a fully manual, multi step monthly reconciliation with a single one click calculation.
  • Automated matching against ~25 specific GL account codes across thousands of ledger rows.
  • Eliminated a recurring source of human error in model code cleanup and category grouping.
  • Produced a reliable, model level CM dataset that now feeds directly into a downstream Python reporting pipeline.
  • Standardised the calculation logic across 6 monthly workbooks, ensuring consistent figures every reporting cycle.
